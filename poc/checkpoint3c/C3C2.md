# Checkpoint C3C2 — Beginner-first UX and playable single/dual layer preview

**Status:** implemented on experimental branch; Windows desktop QA is required after Actions passes.

**Branch:** `poc/v0.2.0-engine-comparison`  
**App:** OpenClipper C3C2 Preview Lab, version 0.2.1  
**Isolated app ID:** `dev.openclipper.custom.previewlab` (does not replace v0.1 production identity).

## Purpose and user-observed regressions

The user tested C3C1 on a Windows laptop. V1 showed a preview frame but Play remained disabled until a second video was selected. After both were selected, V1 appeared still while the fullscreen overlay covered it; hiding V2 exposed V1 working normally and seeking correctly.

**Root cause in C3C1:** `ready()` required both metadata streams, and `duration()` used the minimum of both durations. V2 covered the entire screen at half-opacity. The UI also read object properties for process metrics even though Rust returned a two-element array.

## Delivered in C3C2

- V1 **alone** enables Play/Jeda and seeks across its full valid duration.
- V2 is optional; if provided and visible, it is muted and follows V1 by best-effort clock alignment. Shorter V2 ends before V1 without cutting the V1 timeline.
- Layouts **Video kecil di sudut** (PiP), **Berdampingan**, **Atas dan bawah**, **Bertumpuk**; visibility and opacity controls. These are *live preview compositions only*, not exported video.
- Hamburger/collapsible sidebar, Dashboard, compact quick presets, Mode Mudah/Mode Lengkap. Technical diagnostics are hidden in Mode Mudah.
- Clearly labeled navigation to Proyek Saya, Video Saya, Saran AI, Publikasi. These routes show honest empty states, **not fictional videos or fabricated AI rankings**.
- Dashboard subtitle style preview is a **visual sample only**, not video subtitle rendering.
- CPU/RAM IPC now reads the actual Rust return format `[cpuPercent, workingSetMb]`.
- Browser regression for V1-only import/play/seek, two-file import, layouts, toggles, navigation and runtime JS errors; existing v0.1 import regression still runs.

## Known limitations and explicit non-features

- Preview uses WebView2 `HTMLVideoElement`, not FFmpeg or libopenshot native frame adapters. No native engine selected.
- Playback synchronization is best effort, not verified audio/video drift.
- No saved projects, clip ranking, real AI inference, speech transcription, automatic titles, YouTube acquisition, render/export or social-platform publication. No account tokens or service credentials are collected.
- Default and selected preview layouts are not automatically transferred to output because output does not exist.
- Original v0.1 `Buat Klip` local import remains available in the experimental app; the stable main branch is unchanged.
- Windows process telemetry excludes child WebView2 processes and GPU.

## Windows acceptance checklist

1. Install the Windows **C3C2** artifact from a successful workflow run (different from old C3C1 ZIP).
2. Open Dashboard, collapse/expand the hamburger sidebar, switch Mode Mudah and Mode Lengkap.
3. Choose a font **sample**, ratio 9:16, layout PiP/Berdampingan; click “Terapkan ke Preview Dua Video”. Verify correct ratio/layout selection.
4. **Import only V1.** Check duration appears, click Putar, pause, seek and play. V2 is not required.
5. Import a different V2. Switch PiP, side, stacked, overlay. Visually confirm V1 stays visible in PiP/side/stack. Hide V2 and confirm V1 plays and seeks.
6. Repeat a scrub with V2 visible to check visual seek and clock drift. Use two videos with similar lengths first.
7. Open Mode Lengkap → Diagnostik Teknis. Observe CPU/RAM and browser counters; report if a value remains “—”.
8. Navigate Proyek Saya, Video Saya, Saran AI and Publikasi; verify unavailable operations are clearly marked as planned, not functional.

**Gate:** GitHub Actions green is necessary but not sufficient; real Windows playback QA and usability feedback must pass before considering C3C2 validated.
